# עסקים מוכרים — `known_businesses`

## ⛔ חובה בכל ריצה של Game (מ-17-11-2026)

1. **סנכרון עם המערכת — מיד אחרי ה-SETUP, לפני החיפוש הראשון:**
   ```bash
   python3 known_businesses/known_businesses.py sync
   ```
   מוסיף לקובץ את כל העסקים שנמצאים עכשיו באתר (גם מה שהעובדים העלו אחרי הריצה הקודמת) וכותב את
   `known_businesses/business_types.txt`. אם מודפס `SYNC FAILED` — לכתוב את השורה בטיוטה ולהמשיך.
   (גם בלי זה, `check` / `check-report` / `add` בודקים תמיד גם מול העסקים שבאתר.)
2. **סוג עסק — מהרשימה הסגורה:** את עמודת "סוג עסק" בוחרים מתוך `known_businesses/business_types.txt`
   ומעתיקים בדיוק (למשל פסיכיאטר → "מרפאה / רופא", עורך דין → "משרד עורכי דין"). סוג חדש — רק אם אף סוג
   ברשימה לא מתאים, ומפרטים אותו בסיכום הטיוטה בסעיף "סוגי עסק חדשים".
3. **שמירה לפני הטיוטה:** בכל CHECKPOINT, אחרי שהעסקים של הכתובת נוספו לאקסל ו**לפני** update_draft:
   ```bash
   python3 known_businesses/known_businesses.py add "<האקסל>" --source "רוטינה Game $(date +%d-%m-%Y) מאינדקס ${CURRENT_INDEX}"
   git add known_businesses/known_businesses.xlsx && git commit -m "known businesses checkpoint" ; git pull --rebase origin main ; git push origin main
   ```
   כך כל עסק שמגיע לטיוטה כבר שמור ברשימה, גם אם הריצה נקטעת לפני STEP 3. (האינדקס ממשיך להתעדכן ב-STEP 3 כרגיל.)

למה: ב-02-11 ריצה נקטעה — העסקים של אחת הכתובות הגיעו לטיוטה ומשם לאתר, אבל לא לרשימה; ב-10-11 הרוטינה
סרקה שוב ומצאה אותם שוב, והם הועלו לאתר בפעם השנייה.

## המטרה

שהרוטינה Game לא תדווח שוב על עסק שכבר נמצא. בריצה של 14-10-2026 שניים מתוך 8 העסקים שנמצאו כבר היו במערכת.

`known_businesses.xlsx` — כל העסקים שכבר ידועים:
- כל העסקים שבמערכת (טבלת `businesses` ב-Supabase) נכון ל-14-10-2026;
- כל העסקים מדוחות קודמים של הרוטינה (`excel outputs/` ובתיקייה הראשית — דוחות פגומים דולגו);
- 8 העסקים של הריצה מ-14-10-2026 (מתוך טיוטת המייל).

עמודות: שם העסק, כתובת, שכונה, סוג עסק, קישור, מקור (מאיפה הגיע), תאריך הוספה.

## איך הרוטינה משתמשת בזה

```bash
# לכל עסק מאומת, לפני שהוא נכנס לדוח:
python3 known_businesses/known_businesses.py check "<שם העסק>" "<כתובת>"
#   KNOWN → כבר קיים: לא נכנס לדוח ולא נספר ל-100   (exit 1)
#   NEW   → חדש: נכנס לדוח                          (exit 0)

# בדיקה אחרונה של הדוח כולו לפני השמירה — חייב להדפיס "סה"כ KNOWN: 0":
python3 known_businesses/known_businesses.py check-report "<דוח>.xlsx"

# בסוף הריצה — מוסיפים את העסקים החדשים לקובץ ודוחפים אותו יחד עם index:
python3 known_businesses/known_businesses.py add "<דוח>.xlsx" --source "רוטינה Game 14-10-2026"
```

## איך עובדת ההתאמה

עסק נחשב "כבר קיים" כשיש **אותה כתובת** (רחוב + מספר בית; "שדרות"/"שד'", "ירושלים", מיקוד ו-1/2 לא משנים) **וגם שם דומה** —
אחרי הורדת תארים (עו"ד, ד"ר, בע"מ, משרד...) וסימני פיסוק, בלי חשיבות לסדר המילים.
לכן "כהן ישראל" = "ישראל כהן, עו"ד" באותה כתובת.

שם זהה בכתובת **אחרת** מודפס כ-`NEW (שם זהה בכתובת אחרת — לבדוק)`: הוא נכנס לדוח (אולי פועל גם בכתובת נוספת), והשורה עוזרת לבדוק ידנית.
